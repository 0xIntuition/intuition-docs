An IID scheme tells you what a value identifies and which spellings count as the same identifier. For example, the Wikidata scheme accepts `q42` and returns `int:wd:Q42`. It rejects `Q042` because leading zeros are invalid. A successful check gives you a name you can compare byte for byte. To establish that this Wikidata item describes the person in your catalog, you still need evidence connecting the two records. [Wikidata scheme and examples](https://github.com/0xIntuition/intuition-identifier/blob/3e593247c0e7cb168b37368937167ed146d3868a/schemes/wd.md#test-vectors)

## Read a scheme row

Use **Identifies** to choose the kind of thing you have. An ISRC names a recording, while an ISWC names a musical work. The arrow shows one accepted input and the complete canonical IID. The normalization column summarizes the rule. Follow the scheme name for the full algorithm and rejection cases. The canonical registry has 26 schemes, with 15 in Class A, 10 in Class B and one in Class C. [Canonical registry](https://github.com/0xIntuition/intuition-identifier/blob/3e593247c0e7cb168b37368937167ed146d3868a/registry.json) · [170 canonical test vectors](https://github.com/0xIntuition/intuition-identifier/blob/3e593247c0e7cb168b37368937167ed146d3868a/test-vectors.json)

**Class** tells you where the identity comes from. In Class A, an authority assigns a value. In Class B, the entity has an intrinsic identifying key. In Class C, a recipe derives the value from available facts. **Typing** asks whether the scheme and value tell you the entity type. A bare P0 anchor stores just the IID text. The canonical specification requires both Class A or B and unambiguous typing for P0. A plain `int:wd:Q42` has Class A, but a QID alone leaves the type open, so its atom needs at least P1 identity context. [IID spec §3.2](https://github.com/0xIntuition/intuition-identifier/blob/3e593247c0e7cb168b37368937167ed146d3868a/spec/03-identity-classes.md#32-the-three-classes) · [IID spec §7.2](https://github.com/0xIntuition/intuition-identifier/blob/3e593247c0e7cb168b37368937167ed146d3868a/spec/07-representation-profiles.md#72-the-profiles) · [IID spec §7.3](https://github.com/0xIntuition/intuition-identifier/blob/3e593247c0e7cb168b37368937167ed146d3868a/spec/07-representation-profiles.md#73-scheme-typing)

:::info Canonical specification and packaged copy

Both sources define strong and weak `acct` values. A strong value such as `int:acct:x:295218901` names a platform’s stable account ID and can anchor at P0. A weak value such as `int:acct:github:@torvalds` names whoever holds that handle. The package sets a P1 minimum for weak handles because a platform can reassign them. The canonical bytes stay the same. [Canonical account scheme](https://github.com/0xIntuition/intuition-identifier/blob/3e593247c0e7cb168b37368937167ed146d3868a/schemes/acct.md) · [Packaged eligibility amendment](https://github.com/0xIntuition/packages/blob/4e9af1373b81a453d16bc650983138e35afb97d1/packages/iid-spec/spec/09-registry-governance.md#97-pre-publication-amendments)

The package also accepts typed values within `wd`. A plain QID still needs P1. A value with an active type binding, such as `human:Q42`, can anchor at P0. Dormant bindings are for parsing only. The package adds three whole schemes in Class D, `apple-podcasts`, `letterboxd` and `podcast-index`. Every accepted value in those schemes identifies a typed item in a provider’s catalog and requires at least P1. [Packaged Wikidata scheme](https://github.com/0xIntuition/packages/blob/4e9af1373b81a453d16bc650983138e35afb97d1/packages/iid-spec/schemes/wd.md) · [Packaged provider-local rules](https://github.com/0xIntuition/packages/blob/4e9af1373b81a453d16bc650983138e35afb97d1/packages/iid-spec/spec/09-registry-governance.md#97-pre-publication-amendments)

The packaged text omits canonical §7.8, which separates identity bytes from companion metadata. Chapters 00, 01, 04, 05 and 09 also differ. Use the canonical chapters when implementing the specification and the package documents when predicting what the published library accepts. [IID spec §7.8](https://github.com/0xIntuition/intuition-identifier/blob/3e593247c0e7cb168b37368937167ed146d3868a/spec/07-representation-profiles.md#78-the-atom-creation-model-data-and-companion-metadata) · [Packaged representation profiles](https://github.com/0xIntuition/packages/blob/4e9af1373b81a453d16bc650983138e35afb97d1/packages/iid-spec/spec/07-representation-profiles.md)

:::
