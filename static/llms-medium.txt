# Prepare transactions with the CLI

Applies to V2 · `@0xintuition/cli` 0.1.0 · `@0xintuition/sdk` 4.0.0

Turn a proposed testnet deposit into calldata and a serializable `AgentActionEnvelope`. The CLI executable encodes the call. The SDK builds the plan that an application can present to a human.

## Before you start

Use a Node 22.18+ ESM project. Install the executable and the packages imported by the example. It runs with synthetic read context and requires no wallet or RPC.

## Steps

### 1. Find the encoder

List the core write encoders for MultiVault. Look for `multiVaultDepositEncode`, which accepts a receiver, term ID, curve ID, and minimum shares.

# The SDK read client

Applies to V2 · `@0xintuition/sdk` 4.0.0

For indexed V2 reads, run a Core node and use its [Query API](https://docs.intuition.systems/docs/build/query-core). The pinned SDK read client calls the hosted V1 GraphQL API and is not a V2 read path.

There is no V2 GraphQL endpoint yet; one is planned for Intuition Core. The V1 GraphQL API is documented in the [V1 docs](https://docs.intuition.systems/docs/v1/graphql-api/overview).

## Endpoint mapping

`getIntuitionApiUrl('mainnet' | 'testnet')` selects these V1 endpoints:

| Selection | Endpoint |
| --- | --- |
| `mainnet` | `https://mainnet.intuition.sh/v1/graphql` |
| `testnet` | `https://testnet.intuition.sh/v1/graphql` |

# Triples, counter-triples and nested triples

Applies to V2 · `@0xintuition/ids` 0.1.0 · `@0xintuition/primitives` 0.1.0 · `@0xintuition/protocol` 4.0.0

A triple expresses a claim in three ordered parts. The **subject** is what the claim concerns, the **predicate** names the relationship, and the **object** is what stands on the other side of that relationship. Each part is a term ID. The triple gets an ID of its own, so a second claim can cite the first one.

**Builds on:** [Atoms](https://docs.intuition.systems/docs/concepts/atoms).

**Implemented by:** [ids](https://docs.intuition.systems/docs/reference/packages/ids), [primitives](https://docs.intuition.systems/docs/reference/packages/primitives), [protocol](https://docs.intuition.systems/docs/reference/packages/protocol).

# FeeProxy

Applies to V2 · `@0xintuition/periphery` 0.1.0 · `@0xintuition/sdk` 4.0.0

FeeProxy lets an affiliate charge a disclosed fee on a MultiVault deposit or creation. The Solidity contract ships in the core contracts artifact. The V2 periphery library provides FeeProxy helpers, and the SDK builds higher-level plans.

## Quote a route

`affiliateConfig(affiliate)` exposes the fee recipient and separate deposit and creation rates. `previewDepositFee(affiliate, grossAssets)` and `previewCreationFee(affiliate, grossAssets)` each return the affiliate fee and the assets available to forward. The fee equals `floor(grossAssets × bps / 10,000) + fixedFee`, in native wei.
